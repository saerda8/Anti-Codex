# Anti-Codex 真实任务链路剩余风险审计

日期：2026-06-22

## 已覆盖

- 已有真实链路脚本能验证：模型响应、工具调用、文件创建/运行、真实 MCP 调用、中文最终回复。
- 已有空回复保护：模型返回空内容时会触发重试或明确失败，不让 UI 无限等。
- 已有假执行保护：模型声称已经执行工具但本轮没有真实 tool call 时，会被拦截并要求真实调用。
- 已有 Antigravity 请求排队、取消、会话锁、失败熔断和额度/账号提醒。
- 已有 Manager 检查入口：快速检查、整体检查、真实流量验证、MCP/Skill 检查、插件/应用检查。

## 剩余风险

- 真实 UI 流式渲染还需要更多肉眼验收：假执行文本如果先流出来再被拦截，前端是否干净替换仍要实测。
- 长任务并发仍可能排队过久：多个长请求同时进入时，后面的请求可能先被客户端超时。
- 多轮长上下文下的假执行识别还不够强：历史里有旧工具证据时，模型可能借旧证据说“刚刚做了”。
- Antigravity 桌面端或账号弹窗属于外部状态，Anti-Codex 只能检测和提醒，不能完全消除外部弹窗。
- 插件/连接器目前主要是元数据可见；未授权连接器不会伪装成可调用工具。

## 建议压测任务

- 真实小工具任务：让 Anti-Codex 创建脚本、运行、修 bug、再次运行，确认工具链不是只会聊天。
- 多轮长上下文任务：连续 8 到 12 轮读写文件，确认历史不丢、模型不乱声称执行。
- 并发长任务：同时发起多个长生成任务，确认排队、取消、超时和提醒表现。
- 假执行诱导任务：故意让模型“声称读文件”，确认没有真实工具调用时会被拦截。
- 额度/账号异常任务：模拟或等待 Antigravity 额度异常，确认 Anti-Codex 用自己的提醒系统提示切账号。
