# MCP Worker 派工失败复盘（2026-06-20）

## 事实 (Facts)
- **Antigravity 只读审查错误安排**：Antigravity 被错误地安排执行只读审查任务，由于其不匹配该只读属性，最终导致空结果产出。
- **DeepSeek 契约与并发冲突**：DeepSeek 在被要求不改动文件的前提下，依然使用了实现型成功契约。此外，该 Worker 与主线程在同一时刻并发修改了同一个测试文件，导致最终失败后的归因极其混乱。

## 根因 (Root Causes)
1. **任务类型与工具契约不匹配**：未能根据任务性质（只读/修改）正确匹配并应用 Worker 的执行和验证契约。
2. **共享文件并发冲突**：主线程与 Worker 线程在无隔离机制的情况下，并发对同一个测试文件进行写操作，造成读写竞争与状态覆盖。
3. **路径边界参数错误**：任务在派发或执行中传入的路径参数未能严格遵守 `cwd`（当前工作目录）边界，导致路径解析不一致或越界。
4. **任务无明确文件产出**：对于定义为实现型的任务，任务要求中没有规定清晰的、可供验证的产出文件。

## 本次纠正措施 (Corrections)
- **失败重安排机制**：当 Worker 派工失败后，应当重新评估并安排不会失败的新任务（如调整参数、缩小范围、隔离依赖），而不是直接默认将控制权退回并由主线接管。

## 派工硬规则 (Hard Rules)
- **契约与产出匹配**：实现型 Worker 只能且必须接收**有明确文件产出**的任务。若原始任务没有明确的文件产出，必须重新设计其要求，使其产生可验证的落文件结果（如输出日志、报告或生成的特定文件）。
- **文件独占原则**：每一个 Worker 在执行期间必须**独占其操作的目标文件**。严禁多个 Worker，或 Worker 与主线程并发修改同一个文件。若存在文件冲突，必须重新划分文件范围以确保隔离。
- **路径必须符合 cwd**：所有传递给 Worker 的路径参数必须完全符合 `cwd` 规范，严禁超出工作目录边界。若检测到路径参数错误，应立即纠正并重新派工。
- **任务粒度与调整策略**：
  - **参数错误**：立即修正参数并重新派工。
  - **任务范围过宽**：应将任务拆分为更小粒度的子任务分别派工。
  - **无输出任务**：必须改写为落文件输出。
  - **文件冲突**：重新规划和隔离文件。
- **失败分类与升级边界**：
  - Worker 任务失败后，必须首先对失败根因进行分类，并重新设计粒度更小、针对性更强的任务再次派工，**严禁直接放弃 MCP 模式**。
  - 只有在**连续三次窄化任务**后，仍然因为外部故障（如外部服务崩溃、系统级不可恢复故障等）导致任务无法完成时，才允许将任务升级并临时由主线接管。
- **派工记录规范**：所有派工必须完整记录 `job_id`、执行结果以及具体的产出文件。
