# Anti-Codex Manager UX Gap Audit

## 当前表现
- Manager 已经内嵌在 Anti-Codex 主窗口里，不再打开独立网页，也不走 ChatGPT 登录。
- 面板能显示 8 个 Antigravity 可见模型、同步状态、回滚状态、MCP/Skill、插件/应用、快检和完整检查。
- MCP/Skill 按钮实测通过：MCP 3 个、Skill 100 个，可读可见。
- 插件/应用按钮实测通过：本地插件 183 个、连接器目录 1494 个；当前没有授权连接器时，明确显示真实可调用应用工具为 0，不伪装能力。
- 按钮级检查器已加串行锁，并等待自己的动作完成，避免并发验收时把 MCP/Skill 和插件/应用结果读串。

## 体验风险
- 远程连接器数量很大但真实可调用为 0，用户容易误以为插件“都能用”。这里需要更直白地区分“本地可用”和“远程目录可见但未授权”。
- 长耗时操作目前只有运行中文案，用户仍可能分不清是在同步、校验、还是卡住。
- 账号/代理异常已经有提示，但最好把“拉起 Antigravity”和“重试连接”做成更直接的主窗口动作。
- 模型名展示必须以后端目录为准。前端只能渲染，不能靠猜后缀生成“3.5/3.1/High/Low”等关键显示。

## 建议下一步
- 给插件/应用卡片加一行固定解释：`本地插件/MCP 可直接用；远程连接器只是目录可见，未授权时不会伪装成工具`。
- 给长耗时按钮增加阶段文案，例如“构建候选版本 / 校验哈希 / 重启验证 / 写入报告”。
- 在账号/代理提醒里增加两个动作：`打开 Antigravity` 和 `重新检查连接`。
- 把 Manager 的模型展示继续锁定为后端返回的 `displayName + id`，并保留模型名精确数字的回归检查。
