# Anti-Codex 当前长任务目标与验收清单

更新时间：2026-07-20

## 唯一目标

Anti-Codex 使用体验必须与原生 Codex 一致：在同一个任务里持续对话、真实调用工具、创建和修改文件、运行验证、接受用户纠正、从中断处继续，最后交付可直接使用的实物成果。只回复方案、说明或自述完成，一律不算通过。

固定三层架构不变：

1. 隔离复制并同步官方 Codex 客户端，Codex 负责任务、工具、文件、审批、续跑和界面。
2. 第三方 API 直接使用 CodexPlusPlus 翻译层，只保留 Anti-Codex 隔离所需的小补丁。
3. Antigravity 保留原生模型出口，只通过薄 Chat 适配接入 CodexPlusPlus，不增加第四套任务控制器。

## 自主执行标准

- 长任务只允许用一份完整目标和验收合同启动。Anti-Codex 必须自行检查现状、制定计划、连续调用工具、处理失败、返工和验收，不能依赖主机逐阶段提供实现提示词。
- 主机只负责三件事：提供方额度不可用时在 Gemini 与 Claude 间切换、发现明显偏航时给出用户级纠正、对最终成果做独立验收。主机不得代替 Anti-Codex 编写生产文件、运行生产渲染或把后台成果塞回前台。
- 提供方切换后必须在同一个原生任务中恢复同一个总目标，只允许附带当前事实和未通过项，不得把后续工作拆成新的微任务提示词。
- 如果 Anti-Codex 只输出完成说明、等待下一阶段指令、要求主机给出具体实现步骤，或没有真实工具/文件证据，就判定自主长任务失败。
